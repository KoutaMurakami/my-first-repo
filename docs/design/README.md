# Handoff: フィットネス管理アプリ UI（v1 完成形）

対象リポジトリ: `KoutaMurakami/my-first-repo` / ブランチ `setup/flutter-app-scaffold`（Flutter + Material 3 + Drift）
関連ドキュメント: `docs/ui-design-brief.md`, `docs/requirements-fitness-app.md`

## Overview
筋トレ・食事・からだ（体重/体組成）の記録を1つのアプリにまとめる。ホームで「体重推移」と「今日の栄養の過不足」を把握し、AIが食事アドバイスと筋トレメニューを提案する。ユーザーの基本情報（性別・年齢・身長・体重・活動量・目的・経験・分割法）から基礎代謝・メンテナンスカロリー・目標PFCを算出する。

## About the Design Files
同梱の `Fitness App.dc.html` は **HTMLで作ったデザインリファレンス（動くプロトタイプ）** であり、そのまま本番に使うコードではない。タスクは、このデザインを **既存の Flutter プロジェクト（`app/`）の流儀（Material 3 / `ColorScheme` / `ThemeData` / Drift）で再実装する** こと。
- ブラウザで `Fitness App.dc.html` を開くと動く（`support.js` を同じフォルダに置くこと）。画面上部のチップで全画面を切替可能。
- ロジック（栄養計算・AIメニュー生成・状態遷移）は HTML 内の `class Component` に JS で書かれている。仕様の一次情報として読んでよい。

## Fidelity
**High-fidelity**。配色・タイポ・余白・角丸・インタラクションは確定値。ただしアイコン/ロゴは **未確定**（アプリ名確定後に作成予定）。現在の色付き四角/丸は仮アイコンなので Material Symbols 等に置換すること。

## 共通レイアウト
- 端末幅 390pt 想定。画面左右パディング 20、セクション間 gap 14–16。
- カード: 背景 `surface #FEFDFA`、1px 枠 `outline #E6E2DD`、角丸 16–20、影なし。
- 強調カード（AI系）: 背景 `#1C3330`、文字 `#F3F8F7`（`oklch(0.97 0.006 185)`）、内側の区切り `rgba(255,255,255,0.1)`。
- ボトムナビ（5タブ）: ホーム / マイトレ / 筋トレ / 食事 / からだ。選択中は 48×26 のピル `#DEEBE9` ＋ 文字/アイコン `#103833`、非選択 `#63605C`。下部セーフエリア 24。M3 `NavigationBar` で実装可。
- ナビ非表示画面: 種目選択 / セット記録 / 食品検索 / 進捗写真 / ログイン / 基本情報（← 戻るボタン付き）。

### 3. 筋トレ
1. **分割法カード**: 「分割法 · PPL」「今日は Day 2：プル」。「変更」で展開し、分割法エディタ（基本情報と同一UI、下記）を表示。
2. **AIメニュー提案カード**（強調カード）:
   - 右上に「中級 · 減量 · 週4回」ピル → 基本情報へ。
   - Day チップ（分割法の各日。例「Day1 プッシュ」）で対象日を選択。
   - 理由文（目的×レベル別、レスト目安秒数）。
   - 種目リスト: 種目名 / セット方式 / 「3セット × 8–12回」。
   - 「このメニューで開始」「マイトレに保存」（保存後「保存しました」）、「別の提案を見る」。
   - 生成ルール（JS `aiMenu()`）: 種目数 初心者3 / 中級4 / 上級5。目的別 — 筋肥大 3–4セット×8–12回 レスト90秒・最終種目ドロップ（中級以上）／筋力 ピラミッド 3–5回 レスト180秒／減量 スーパーセット 12–15回 レスト45秒／維持 3×10 レスト60秒。部位プールを日の部位からラウンドロビンで選ぶ。実装時は LLM に置換可。
   - ※「このメニューで開始」は現状プッシュAのセット記録を開くだけ。実装時は提案内容でセッションを生成すること。
3. **中断中カード**（中断時のみ）: 「中断中：プッシュ A」「n / m セット記録済み」「中断までの記録は保存されています」、「再開する」/「ここまでで終了」。
4. 「マイトレから開始 →」（保存件数表示）、「＋ 種目を選んで記録する」（破線）→ 種目選択。
5. **トレーニング履歴**: 見出し右に「総セット数 · 消費kcal」。行: 名前 / 日付・種目数・時間、右に「18セット」＋消費kcal（テラコッタ 11px/600）。

### 5. セット記録（トレーニング中）
- ヘッダー「← 中断して保存」/「● 記録中」。見出し＋「n / m セット完了 · 自動保存」。**経過時間表示は無し（削除済み）**。
- **レストタイマー使用スイッチ**（ユーザーが選択。初期値は設定/Tweak）。ONで各セット行に「休憩」列が出る。
- レスト中バナー（`#E6F3F1`）: 残り mm:ss ＋「スキップ」。
- 種目カード:
  - 右上 **セット方式ドロップダウン**「ピラミッドセット ▼」→ ストレート/ピラミッド/ドロップ/スーパー/ジャイアント。ストレート以外は説明文を表示。
  - 行グリッド: レストON `20px | 1.3fr | 1fr | 50px | 44px | 44px` / OFF `22px | 1.3fr | 1fr | 64px | 52px`。列 = # / 重量(kg) / 回数 / 前回 / 完了 / 休憩。
  - 重量・回数は **インライン入力**（decimal / numeric キーボード、中央揃え 15px/600）。
  - 前回列: 前回値。重量が上回ると「↑」＋ティール。
  - 完了 ✓: 未完了=白アウトライン、完了=`#244A45` 塗り。再タップで取消。完了してもレストは自動開始しない。
  - 休憩ボタン: 押すとそのセット起点でレスト開始、ボタン内に残り秒。再タップで停止。
  - **フォーストレップ（補助レップ）**: セット番号をタップ → 詳細パネル（淡テラコッタ `#FEF5F0`）を展開。
    - セグメント「最後の数回だけ補助 / セット全体を補助」
    - 部分補助: 「補助してもらった回数」± ステッパー（36×36）、「自力 8回 ＋ 補助 2回 = 計 10回」
    - 全体補助: 「このセットの n回 すべてを補助ありとして記録します（自己ベスト・前回比較の対象から除外）」
    - 補助者チップ: パートナー / トレーナー / セルフ（片手補助）
    - メモ入力、「補助なしに戻す」「閉じる」
    - 閉じた後は行の下にバッジ「補助 +2回 · パートナー」/「セット全体を補助 · トレーナー」＋メモ。番号セルもテラコッタ淡色に。
  - 「＋ セットを追加」（直前セットの値を複製）。
- 「トレーニングを終了」→ 履歴に追加（中断後の終了は meta に「途中終了」）。

### 6. 食事
- 日付ピル、カロリーサマリ（残り / 進捗バー / PFC 3本）、時刻ベースのタイムライン（朝昼夕の固定枠なし）、微量栄養素充足度（主要5件）、「＋ 食事を記録する」。

### 7. 食事を記録
- 上部「今日の残り」カード（ホームと同じ見た目）。食品を追加すると見出しが「この食事を記録した後の残り」になり、PFC・不足栄養チップ（最大5件）が**追加後の値でプレビュー**される。
- タブ: **マイリスト / 検索 / 写真**
  - マイリスト: 定番セット（例: 朝の定番・昼の定番・トレ後）。各行に食品名・量、kcal・P、「追加」で中身を一括追加。
  - 検索: 入力、未入力時は「不足を補うおすすめ」順（不足栄養を多く補える食品を上位に、タグ例「カルシウム +220mg」）。＋で追加。栄養成分は自動入力。
  - 写真: AI推定（今後対応）のプレースホルダ。
- 「このミールに追加済み」: 行ごとに×削除、合計、「この内容をマイリストに保存」。
- 「記録する」→ 摂取に加算してホームへ。

### 11. 基本情報（設定）
- サマリ（強調カード）: 基礎代謝 / メンテナンス / 目標摂取（kcal）、目標 PFC、算出式の注記。
- からだ: 性別（セグメント）、年齢、身長、体重、目標体重、体脂肪率（任意）。
- 日頃の活動量（ラジオ5段階）: ほぼ座りっぱなし ×1.2 / 軽い活動 ×1.375 / 中程度 ×1.55 / 活発 ×1.725 / 非常に活発 ×1.9。
- トレーニング: 目的（減量/体型維持/筋肥大/筋力アップ）、経験（初心者〜半年/中級 半年〜3年/上級 3年以上）、週の回数（1–6）、**分割法**。
- **分割法エディタ**（筋トレ画面と共通コンポーネントにすること）:
  - プリセット: 全身法 / 上下2分割 / PPL / 4分割 / 5分割 / カスタム。各説明文あり。
  - 日リスト「Day n ＋ 名称」。「部位を編集」で部位チップ（胸/背中/脚/肩/二頭/三頭/腹筋/臀部、複数選択）。編集するとラベルは部位名の連結に変わる（例「胸・三頭」）。
  - カスタム時のみ「＋ 日を追加」（最大7）/「− 最後の日を削除」（最小1）。
- メンテナンスカロリー: 自動計算値を表示、スイッチONで実測値の手入力で上書き。
- 「保存する」。

## 計算ロジック（JS `calc()` 準拠）
- 基礎代謝: 体脂肪率あり → Katch-McArdle `370 + 21.6 × 除脂肪体重`、なし → Mifflin-St Jeor `10w + 6.25h − 5age + (男+5 / 女−161)`。
- TDEE = BMR × 活動係数（手入力があれば優先）。
- 目標摂取 = TDEE + 目的補正（減量 −400 / 維持 0 / 筋肥大 +300 / 筋力 +200）を10kcal丸め。
- P = 体重 × 2.2g（減量）/ 2.0g（その他）、F = 摂取 × 25% ÷ 9、C = 残り ÷ 4。

## State Management（主なもの）
- `profile`: sex, age, height, weight, target, bf, act, goal, exp, freq, maintManual, maint
- `split`, `splitDays[{label, parts[]}]`, `focus`（AI対象日）
- セッション: `done{key}`, `edits{key:{w,r}}`, `extra{exIdx:[sets]}`, `exType{exIdx}`, `assist{key:{n, scope:'part'|'full', by, memo}}`, `restOn`, `restLeft`, `restKey`, `paused`
- 食事: `draft[]`, `logged[]`, `mealLists[{name, foods[]}]`, `mealTab`
- 永続化: 既存 Drift (`app_database.dart`) に Workout/Set/Assist/MealList/Profile/SplitDay テーブル追加を推奨。セット記録は1セットごとに即保存（中断＝保存済み状態のまま `paused` フラグ）。
